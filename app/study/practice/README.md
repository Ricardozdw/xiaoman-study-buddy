# 练习线交接

**合并接手请先读：[练习线合并交接（Claude Code / Codex）](../../../docs/交接/3-练习线-合并交接.md)。** 该文档统一说明最终第三轮规则、启动配置、接口、验证及与最新计划线的整合风险；以下较早记录仅供追溯。

当前在 `feat/practice-line` 分支开发。只改练习目录、新提示词及自己的测试；不改共用表、对话壳和其他线。

当前以第三轮页面方案为准：不采集把握度，按对错分类；复习入口进入“做题历史”，不显示统计说明。下文早期交互记录已被本节替代。

## 第三轮当前规则

- 答题前、提交后、历史详情均不显示把握度；作答与草稿请求不再包含该字段。旧客户端携带的字段被忽略，不存入新记录。共用表的非空 confidence 列仅保留空占位，不修改共用表或旧 Attempt 的值。
- 分类仅看对错：答错为待巩固，答对不再因旧把握度进入待巩固；停止优先复习标签。旧 priority 字段始终为 false，历史把握度字段只保留接口读取兼容，不用于页面或分类。
- 首页“去复习”进入“做题历史”，筛选依次为“待巩固”“答对的题”“全部”，默认仍为原错题筛选。有效题目反馈仍独立排除，可编辑、撤回，撤回后按原对错恢复。
- 保留逐题勾选、半选、全选、15题上限、只练所选与单题变式；保留正确答案、解析和折叠原文。未新增规划模块对接。
- wrong_count 与 consolidate_count 现均代表未被反馈排除的答错题数；正确率及同一原题链仅取最近一次作答的去重口径不变。页面删除统计说明及旧把握度说明，保留原有计数展示。

## 本地查看

按根 README 启动后端 8787、前端 5173 后，打开：

http://127.0.0.1:5173/src/lines/practice/preview.html

这是独立验收页，未接入共用对话页。没配模型时全部题目标“模拟”，只验证流程，不代表出题质量或延迟达标。

在这个页面点击“上传 PDF”选择本机文件，真实上传原件并按页读取；完成后显示文件名、页数和文字数，再点“根据这份 PDF 出题”。支持文字版 PDF，每份最多 20 MB / 100 页 / 10 万字。重复文件复用资料；同一资料、题数、难度的题组复用题库，页面会注明。上传或切换资料时，不再显示上一份资料的题目卡。

本地练习上传使用 `POST /api/practice/materials`（multipart 的 `file` 字段）；`GET /api/practice/materials` 只列出当前会话导入的资料。`GET /api/practice/status` 仅显示模型配置情况，不返回密钥、不代表实时连通性。资料和题目均按服务端会话隔离。

根页面 `/` 的“交资料”和资料问答仍为其他线的地基占位；本分支不修改它们。端到端上传练习请使用本页，后续由 A 接入共用对话壳。

## 本机模型与样例

用户已选定 `deepseek-v4-pro` 主用、`qwen3.7-plus` 备用，见本目录 `models.json`。FAST / STRONG 两档都按同一顺序自动降级，不改底座模型网关。

本机 `.env` 设置 `LLM_CONFIG_FILE=app/study/practice/models.json`；密钥填在已有的 `DEEPSEEK_API_KEY` 和 `DASHSCOPE_API_KEY` 中。默认按 DeepSeek 官方和阿里云百炼中国内地接口准备；其他服务平台或区域需要调整对应 base_url。真实连通性和思考参数仍须实测确认。

测试 PDF 及按页文字只保存在被 Git 忽略的 `data/practice/samples/` 中，不上传仓库。可用下面的本地工具给指定测试会话导入资料页（不调用模型，不替代资料线上传功能）：

```bash
.venv/bin/python -m app.study.practice.import_sample --pdf /path/to/sample.pdf --user-id <本机测试会话身份>
```

工具按文件哈希去重、保留原 PDF 页码，并在导入后读回全文核对。更换文件版本会生成新讲次，不覆盖旧资料和做题记录。

## 已有能力

练习交互更新：题数由用户输入 1–15；真实出题按最多 5 题一批生成并核对，页面以圆环显示处理中、不虚构百分比，并禁用重复提交。单道和批量错题换问法共用这一等待反馈。批量最多选择 15 道，允许跨讲次，各题仍只使用原讲对应页，不混拼资料。

“休息一下，保存退出”将当前题号、已选答案、把握度和用时保存到服务端；刷新后先显示继续入口，暂停时间不计入答题用时。未提交草稿另有本机备份。暂停不会完成任务、不会删除作答记录。

暂停后回到可操作的首页：“继续之前的练习”置顶，同时保留 PDF 上传、出题和错题本入口。可暂停多组，开始另一组不会丢失之前的暂停进度。最后一题提交后，原休息按钮位置改为唯一的“看结果”按钮。

答对、答错各有 10 句自然回应池，每次新作答随机取句，同一作答刷新时保持一致；把握度差异继续体现在后续回应和复习安排中。出题和换问法等待文案统一为“稍等哦~正在把知识点按在地上，摩擦成题~”。

把握度选择即时显示提示，提交后的反馈结合对错区分回应。掌握度使用最近 20 次加权记录，答对但低/中把握的贡献分别为 0.65/0.85，高把握或未选择为 1；答错为 0。未选择不记录为用户选择。低把握答对也安排次日巩固；完成仍只看是否做了。

“这道题有问题”可选答案/解析、题干/选项歧义、出处或其他，附可选说明；返回对应确认，刷新后保留报告状态，同类型重复提交不重复写 bad case。报告不取消作答、不自动改标准答案。

- 按讲出题、出处原句核对、独立盲答自检、不合格题丢弃；生成失败不以假结果冒充。
- 同一讲、同一正文版本、题数与难度的普通题组复用题库；每次练习单独记录作答。
- 单卡答题、提交后显示解析、手动下一题、完成总结和回看。刷新按服务端记录恢复。提交重传不重复记分。
- 错题按最后一次作答去重；换问法保持原知识点和原页。重做答错也完成，历史作答永不删除。
- 掌握度用最近 20 次指数加权正确率，较新作答权重更大；按简化 SM-2 安排复习，有未解决错题则次日再复习。
- 用户报告问题进入共用 bad case 表。模型调用记录区分厂商返回用量与估算用量。
- 不同用户按服务端身份隔离，不接收用户自行指定 user_id。

## 接口（已有三个入口保留）

| 接口 | 用途 |
| --- | --- |
| POST /api/quizzes | lecture_id、count（1–15，默认 5）、difficulty、mode（practice/review）、question_ids、task_id |
| GET /api/quizzes/{quiz_id} | 恢复本组题，只返回已作答题的答案和解析 |
| POST /api/attempts | question_id、answer、quiz_id、seconds、confidence；同组同题第一次提交为准 |
| GET /api/mistakes | 尚未重做正确的错题，一道原题及其变体只算一条 |
| POST /api/practice/reports | question_id、必选 category、选填 reason、quiz_id / attempt_id；重复提交更新同一反馈 |
| GET /api/practice/reports/{question_id} | 当前用户的反馈详情 |
| DELETE /api/practice/reports/{question_id} | 撤回反馈，恢复原分类 |
| GET /api/practice/learning?lecture_id=... | 全部题目、错题、答对待巩固、已反馈问题与作答历史；推荐顺序由后端给出 |
| GET /api/practice/review-due?on=YYYY-MM-DD | 给计划线的到期知识点和错题；on 只查询，不修改时钟 |
| GET /api/practice/stats | 按 PDF 汇总有效正确率、错题/待巩固/排除/未标注数量；accuracy 可为 null（无有效作答） |

普通出题响应保留 `lecture_id / label / questions`，增加 `quiz_id / mock / notice / reused`。作答前不下发标准答案、解析和原文引用。页码存在题目 `source.page`；提交后 `source` 才带核验过的原句。

## 等待对接

- **A**：把 `PracticeWorkbench` / `QuizCard` 接到共用对话。组件提供 `onActiveChange`（收起历史答案、关闭原文）和 `onComplete`（刷新左栏和看板），共用层未获授权前不改。
- **资料线**：只通过 `fetch_lecture_pages(user_id, lecture_id)` 取正文；地基对未知讲的样例回退不能当真实正文。
- **计划线**：发起练习时传 `task_id`，整组作答后才将该任务设为 done；不依赖正确率。没传则仅发 `events.name=practice_quiz_completed`，包含 quiz_id / lecture_id / mode / task_id / count，等待计划线消费。不会额外新增任务。
- **看板线**：使用 practice/stats 聚合接口。地基现有看板的固定数据和错题统计不在本线改动范围内。
- **问答线**：识别出题意图后调用 POST /api/quizzes，再渲染本线组件。

## 把握度与题目问题反馈（当前实现）

- 把握度 `"" / low / medium / high` 在提交答案时随 Attempt 固定保存；同组同题重传不能改写。历史未知文本保留原值并标为未映射。
- 统一规则在 `learning.py`，正确率不做把握度加权。按“原题及关联复练”分组，仅取最近一次作答参与已练内容统计；全部 Attempt 历史保留。复练高把握答对仅表示本轮通过。
- 题目反馈使用现有服务端数据库（开发环境 SQLite），不是浏览器 localStorage。身份来自原有会话。有效状态/编辑撤回历史保存在 StudyEvent，沿用 BadCase 库保存反馈索引；不改变公共题目或答案，不新增表。
- 当前用户有效反馈会暂停这一原题链的统计与复习推荐（包括已有变式，避免传播争议题）；独立题目即使知识点相同也不受影响。撤回后用原作答恢复分类。保存反馈、状态与知识点统计在同一事务内，失败整体回滚。
- 推荐顺序：高把握错题、其他错题、低把握答对、中把握答对。复用原批量再练接口；后端再次验证候选资格。`practice.rephrase/v3.md` 要求改变情境、条件或干扰项，保留原知识点和核验出处。
- `GET /api/practice/stats` 保留 week_attempt_count / mistakes_pending 兼容字段；新增汇总范围和计数，原 confidence 加权 mastery 不再作为掌握指标下发。其他角色接入时应读取 accuracy（无有效作答为 null），避免把空统计当成 0%。
- 本次不提供审核、自动修正公共答案、维护者通知。服务端记录不等于维护者已阅读；Supabase 生产部署仍未验收。

针对本轮的离线检查：`.venv/bin/python -m pytest -q tests/test_practice_learning.py`；前端、全量 pytest 与 golden 回归沿用上面的命令。

## 页面精简（首页 / 答题 / 复习）

`preview.html` 通过 `preview.tsx` 直接挂载 `PracticeWorkbench`，它是实际维护源，不是另写的静态演示页。本轮只调整本线 React 组件与样式，不修改模型、分类、统计、反馈持久化或共用对话页。

- `PracticeWorkbench` 管理三个互斥视图；首页仅提供资料、概览、设置和折叠的未完成练习。顶部返回保存成功后才离开答题页；失败保留当前选择。
- `QuizCard` 展示当前题目；完成后显示简短结果，“回顾本套题”限定在该 quiz。`QuestionReviewList` 复用到题组回顾和当前 PDF 复习，后者仅列已答题，默认错题。
- `LearningSummary` 常驻正确率、错题和待巩固三个指标，并显示答对、答错、已反馈三类计数标签；统计口径放在默认收起的统计说明中。原文、历史按需展开，不重复展示最新解析。
- `FeedbackPanel` 使用原生 dialog，提供键盘焦点约束、取消、编辑、撤回及重复提交保护；保存仍走服务端原接口。主页面只展示短反馈和必要标签。
- 题目复选框默认显示，按当前筛选直接勾选；全选不截断，超过15题提示并禁用开始。只发送所选题目，失败保留选择。

前端结构回归在 `web/src/lines/practice/learning.test.ts`；交互仍需使用上述预览地址连接后端实际点验。


## 第二轮页面调整

- 首页顺序为继续练习、新建练习、学习概览。新建练习合并 PDF 选择/上传及题数难度，删除出题说明入口；概览旁统一提供去复习入口。
- 复习取消批量模式；每行显示复选框（有效反馈禁用），全选仅作用于当前筛选列表，支持半选与取消，切换筛选清空选择。上限仍为15题，超限提示用户调整，不静默截断。底部开始按钮仅在选择1–15题时启用。
- 手动指定 question_ids 可复练未被排除的已答题（包括普通答对），仅生成指定题目；未指定时的原推荐能力与排序保留。推荐标记及统计不因单纯选题而改变。服务端仍校验所有题目归属与反馈状态。
- 概览可见标签分别读取 correct_count / wrong_count / reported_count，与原正确率和去重口径一致；移除有效作答及未标注计数字段的界面展示，原数据与计算保留。
