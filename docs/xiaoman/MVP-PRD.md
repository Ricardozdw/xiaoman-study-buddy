# 小满学习搭子 · MVP PRD

2026-11-03 · @路明泽

MVP 用 2 周做出一个能真实跑通的网页版学习搭子，验证一件事：**用户第二天打开时，小满能接上昨天，并告诉他今天该学的三件事。**

## 背景与目标

**问题**：想认真学东西的人（备考、跟网课）手里资料很多，但每天打开并不知道该学什么；错题和忘掉的内容没人记；中断几天就容易放弃。NotebookLM、ChatGPT 这类工具围绕“资料”，问一句答一句，不会主动安排。

**一句话定位**：你只管上课和交资料，小满记得你学到哪，每天告诉你该学的三件事，让你看得见自己在进步。

**目标用户**：25–30 岁、有明确学习目标（备考或跟网课，主打哪个待定；演示先用 PMP）、想记录学习过程的人。网页端优先。

**核心价值**

1. **连续性**：做题、错题、进度都记下来，第二天能接上。学习记录就是记忆，不做通用聊天记忆。
2. **主动性**：用户不用想“今天学什么”，小满从大目标拆出今天三件事。
3. **陪****伴不施压**：不追责、不连续打卡，中断后回来也有台阶下。

**MVP 成功标准（第 10 天演示时）**

- 用一门公开课的真实 PDF，现场走完“第一天”和“第二天”两段，不靠截图。
- 第二天的三件事里至少一件来自昨天的错题，错题重做后掌握度变化可见。
- 问答和出题达到评测线（见“验收与指标”）。

## MVP 范围

MVP 只做跑通“定目标 → 交资料 → 学和练 → 第二天接上”这条主线必需的功能，其余都留到以后。

| 模块 | MVP 做 | 先不做 |
| --- | --- | --- |
| 目标 | 对话里问目标、考试日期、讲数、每天时间；目标拆解卡 | 多个目标并行、手动编辑完整计划 |
| 资料 | 文字版 PDF；Word / PPT 转 PDF 后处理 | 图片、扫描件（第 5 天前有余力再加）、网页链接、录音 |
| 学习文档 | 要点、知识点、术语，带页码 | 思维导图、闪卡 |
| 问答 | 整讲全文交给模型，回答标页码并核对 | 知识库检索（以后换自建知识库）、跨多讲问答 |
| 做题 | 单选题、判分、解析、错题本 | 简答题、模拟考试 |
| 今天三件事 | 自动排、打勾、换强度、中断后回来 | 手动加任务、改期、拖动排序 |
| 看板 | 每讲掌握度、这周学了几天、目标进度 | 长期趋势、导出报告 |
| 小满 | 5 个露出时刻、状态表情 | 桌宠、成长收集、语音 |
| 平台 | 电脑网页、简单登录 | 手机端设计、推送通知、飞书 / 微信接入、对外内测 |

技术上也先不做：知识库（Dify 的和自建的）、自动部署；后端底座里用不上的飞书 / 微信 / 网页抓取 / 写草稿 / 安全输入区先关掉。

## 核心用户流程

（图：核心用户流程 · 第一天 5 步，回来分 3 种——见在线文档）

第一天是一条直线；之后每次打开，按隔了多久分三种开场，每种都只让用户做一个决定，然后回到“今天三件事”。三种开场的细节见 F6。

## 功能需求与验收标准

共 8 个模块。每条验收标准都要在浏览器里点一遍确认，AI 说“做好了”不算。

### F1 目标拆解

- 第一次见面，小满在对话里问：目标和日期、课程一共几讲、已学到第几讲、每天大概多少时间。每题都有快捷回复，也能自己输入。
- 小满出一张**目标拆解卡**：分阶段（学新讲 / 刷题 / 冲刺），每天三件的来源，默认强度。点“好”才生效，可撤销；“说说怎么改”用一句话重排。
- 验收：确认后左栏立刻出现今天三件；撤销后左栏清空；用户没回答的项不会被当成用户的选择。

### F2 交资料与学习文档

- 点 ＋ 或把文件拖进对话；对话里出**进度卡**：按页读文字 → 整理成学习文档，显示读到第几页。
- 好了以后出**文档摘要卡**（3 条要点 + 知识点数 + 术语数），点“打开全文”在右侧工作台看完整学习文档。标“AI 整理，可以改”。
- 验收：一份 30 页左右的文字版 PDF，2 分钟内出学习文档；每个知识点都带页码；解析失败时进度卡显示“失败”和重试按钮；重复上传同一个文件不重新处理。

### F3 资料问答

- 直接在输入框提问；输入 @ 可以指定问哪一讲，不指定就问最近在学的一讲。
- 回答里的关键结论标【第 N 页】，点开在右侧看那一页原文，引用的句子高亮。资料里没有的，说“你的资料里没提到”，再给通用知识。
- 验收：出处核对通过率 ≥ 95%；资料里没有的 20 个问题都诚实说明；回答边生成边显示；回答下有 👍 / 👎，点 👎 进 bad case 库。

### F4 做题

- 按一讲出 5 道单选题（强度不同题数不同），每题标出处和难度。
- **一组题一张卡**，原地换题；答完看解析，点“下一题”才换；做完收成一行总结，可展开回看。做题时前面带答案的对话先收起，右侧原文面板自动关闭。
- 答错的题进错题本，并自动进之后的“补一补”。重做时答错不卡住，这道过几天换个问法再出。
- 验收：出题评测达线；对话里每组题只占一张卡；做题时看不到前面的答案；题目卡上有“这道题有问题”，点了进 bad case 库。

### F5 今天三件事与强度

- 每天最多三件，各从一处来：**学新的**（按进度该学的讲）、**练一练**（给学过的讲出题）、**补一补**（错题和快忘的内容）。某处没东西就由另外两处顶上。标“先做这件”。
- 小满一件一件带着做：做完一件自动勾上，主动引导下一件（“开始 / 晚点再做”）。左栏任务可以直接点开始。做了就算完成，对错只影响掌握度。
- **强度三档**：轻松约 15 分钟 / 正常约 30 分钟（默认）/ 冲刺约 50 分钟。件数不变，变的是每件的分量。用户在左栏直接切；用户说“今天只有 15 分钟”，小满出建议卡。
- 验收：任何操作都不会让某天超过三件；切强度后左栏文字立刻更新；三件做完有收工反馈并告诉明天的三件。

### F6 中断后回来

- 没做的任务不堆积，回来那天仍最多三件；开场不提断了几天。
- 落后不多（在复习余量内）：只出**一张卡**——今天轻松一点 + 落下的讲从复习时间里补，考试计划不变。点完才带第一件。
- 落后较多：出**重排卡**，给 2–3 种补法让用户选。超过 7 天没来：先问目标还算不算数（照旧 / 日期变了 / 先休息一阵）。
- 验收：每次只让用户做一个决定；所有改动点了才生效、可撤销；“先休息一阵”后不再排任务。

### F7 小满的露出时刻

- 5 个时刻：每天第一次打开（大形象打招呼）、状态跟着事情变（在想 / 开心 / 安慰）、收工和里程碑（大一号的庆祝）、空状态、拆解卡和建议卡。
- 验收：做题时只留头像；不出现负面表情和责备的话。

### F8 看板

- 对话里问“这周学得怎么样”给摘要卡，完整版在右侧：这周学了几天、本周做题数、待重做错题、每讲掌握度、目标进度。
- 验收：不出现“连续 N 天”；重做错题后掌握度变化可见。

## 产品规则（不可违反）

这些规则优先于任何单个功能，前端、后端和 AI 工作流都要遵守。

1. **每天最多三件**。已完成的也占名额；想多学就加强度，不加件数。
2. **改计划先出建议卡**。来自小满或 AI 的任何变更，用户点了才生效，生效后可撤销。用户自己在界面上操作（比如切强度）直接生效。
3. **一次只让用户做一个决定**。不同时推多张卡；点完当前这张再往下走。
4. **不追责、不制造亏欠感**。不做连续打卡，不说“你断了几天”，没做的不堆到今天，答错说“常错，没关系”。
5. **做了就算完成**。任务完成看是否做了，对错只影响掌握度；完成记录永不丢失。
6. **默认值不算用户的选择**。用户跳过的项要写明“先按……安排”。
7. **不编造来源**。回答和题目标的页码必须核对得上，对不上就去掉；资料里没有就直说。
8. **模拟能力要标注**。没接真实能力的地方标“模拟”，AI 生成的内容标“AI 整理，可以改”。

## 界面与交互

只有一个对话页。做什么都从对话开始，结果以卡片形式出现在对话里；长内容在右侧工作台打开。可点击的参考：[demo](https://claude.ai/artifact/QNQPNJgPJin1rsqk4HqLvM)。

**布局（电脑网页）**

| 区域 | 放什么 |
| --- | --- |
| 左栏 | 今天三件事（可点、带来源标签）、强度切换、我的资料（每讲掌握度） |
| 中间 | 和小满的对话流 + 快捷回复 + 输入框（＋ 交资料、@ 指定某讲） |
| 右侧工作台（按需打开） | 学习文档全文、原文某一页、完整看板 |

**对话里的卡片（7 种）**

| 卡片 | 什么时候出现 | 用户能做什么 |
| --- | --- | --- |
| 目标拆解卡 | 第一次定目标 | 好 / 说说怎么改 / 撤销 |
| 进度卡 | 交资料后 | 看进度、失败时重试 |
| 文档摘要卡 | 资料整理好 | 打开全文 |
| 题目卡 | 做题 / 重做 / 练习 | 作答、看解析、下一题、展开回看 |
| 建议卡 | 小满想改计划或强度 | 就这样 / 先不用 / 撤销 |
| 重排卡 | 中断后落后较多 | 选一种补法 / 撤销 |
| 收工卡 | 三件做完 | 看明天的三件、看看板 |

**对话流的约定**

- 每天第一次打开有日期分隔线和欢迎区。
- 卡片原地更新，不重复往下堆；做完的卡收成一行。
- 快捷回复只给当下说得通的选项（已经是“轻松”就不再问“只有 15 分钟”）。
- 手机端 MVP 不单独设计，窄屏只保证不坏：左栏隐藏，工作台全屏。

## AI 能力与数据

两周内不用知识库，走**直接方案**：后端把 PDF 按页抽成文字存起来，每次把这一讲全文（带页码）交给 Dify 工作流里的模型。一讲课件一般几千到两三万字，模型一次装得下。技术栈（2026-11-04 更新）：后端以开源项目 Personal-Agent（MIT，FastAPI + LangGraph，https://github.com/hubooooooo/Personal-Agent）为底座 + Supabase 数据库和文件存储 + React 前端；不用 Dify。每个 AI 能力是一个版本化提示词文件 + 一个后端函数，经底座的模型网关调用；模型一主一备，网关出错自动切备用，评测后定谁当主。功能和验收不变。

**两个替换口**（以后换方案只改后端这一层）

- **取资料内容**：现在返回整讲全文，以后接自建知识库时改成返回检索到的片段。
- **AI 能力函数**：每个 AI 能力封装成一个后端函数，读提示词文件、经底座模型网关调模型；记 token、写 bad case、校验 JSON 都在这一层。

**AI ****能力（6 个，提示词由“负责”一列的人写，函数由 D 写****）**

| 工作流 | 输入 | 输出 | 负责 |
| --- | --- | --- | --- |
| 学习文档 | 一讲全文（带页码） | 要点、知识点、术语，各带页码（JSON） | F |
| 出题 | 一讲全文 + 题数 + 难度 | 题干、选项、答案、解析、页码、难度；自己再答一遍，对不上的丢掉 | F |
| 错题换问法 | 原题 + 对应页原文 | 同一知识点的新题 | F |
| 问答 | 问题 + 一讲全文 | 回答（流式），关键句标【第 N 页】+ 原句 | E |
| 理解用户想干嘛 | 用户一句话 | 提问 / 出题 / 调安排 / 闲聊 | E |
| 小满开场与建议 | 昨天的记录、今天的安排、中断天数 | 开场白和建议卡文案 | E |

目标拆解、今天三件事、强度、中断后回来、掌握度**都用后端规则算，不用 AI**，由 D 负责。

| 目标 | 目标、考试日期、讲数、阶段计划、重排记录 |
| 资料 | 哪一讲、原件、处理状态、文件哈希 |

## 成本估算

两周 MVP 的模型费用不高，但直接方案每问一句都要把整讲全文重发一遍：同一个重度用户，一天要花 **80–180 万 token**，接上知识库后约 **24 万**，差 3–7 倍。所以知识库是“两周内不做”，不是“不考虑”；下面写清了什么时候必须上。

**假设**（都要在模型选定后用真实数字替换）

- 一个重度用户上一天课，交 3 讲资料，每讲约 5 万字，共 15 万字；当天问 10 个问题、每讲出一组题。
- 1 个中文字按 1 个 token 算（偏保守，不同模型约 0.6–1）。
- 单价举例：输入 2 元 / 百万 token，输出 8 元 / 百万 token。**这是假设值**，选定主备模型后按官网价格替换。

**一个重度用户一天的用量**

| 调用 | 直接方案（每次带一讲） | 直接方案（跨讲提问，带全天） | 接知识库后 |
| --- | --- | --- | --- |
| 学习文档 3 次 | 15 万 | 15 万 | 15 万（仍要读一遍全文） |
| 出题 3 次 | 15 万 | 15 万 | 3 万（按章节取片段） |
| 问答 10 次 | 50 万 | 150 万 | 5 万（每次只带 5 千字片段） |
| 开场、换问法等 | 1 万 | 1 万 | 1 万 |
| **输入合计** | **约 81 万** | **约 181 万** | **约 24 万** |
| 输出合计 | 约 2.5 万 | 约 2.5 万 | 约 2.5 万 |
| **每天约（元）** | **1.8** | **3.8** | **0.7** |
| **每月约（元，30 天）** | **55** | **115** | **20** |

算法：每天成本 = 输入 token × 输入单价 + 输出 token × 输出单价。还有一个硬限制：15 万字已经超过不少模型的上下文长度，直接方案根本发不进去一整天的资料，只能一次带一讲。

**两周 MVP 自己的费用**：只有小组自测和评测在花钱。跑一遍评测约 200 万 token，两个模型各跑 20 遍约 8000 万 token，按上面的举例价约 160 元；加上日常测试，模型费用在几百元量级。不用 Dify 后没有平台套餐费，另计一台后端云服务器的费用（待定）。底座自带每人每天 / 每月费用上限，人均上限定了就能配。

**MVP 里就要做的省钱办法**

- 一次只带一讲；跨讲提问先提示用 @ 选讲。
- 学习文档和题目生成一次就存库复用，不重复调用。
- 同一讲连续提问时用模型的上下文缓存（多数厂商对重复输入按更低价格计费，具体折扣以厂商公布为准）。
- **后端记录每次调用的输入 / 输出 token**，按用户、按能力汇总。上面的估算以后用真实数据替换。

**什么时候必须上知识库**（满足任一条就开始做自建知识库）

1. 进入真实用户阶段，或人均每天模型成本超过上限（上限待定，和定价一起定）。
2. 用户需要跨讲、跨课程提问，或单讲资料超过模型上下文的一半。
3. 问答响应时间超过非功能要求里的目标。

切换时只改后端“取资料内容”这一层，前端和工作流不动。

## 非功能要求

| 方面 | 要求 |
| --- | --- |
| 速度 | 30 页左右的 PDF 2 分钟内出学习文档；问答 5 秒内开始出字（流式）；出 5 道题 30 秒内 |
| 稳定 | 主模型出错或额度用完时自动切备用模型；AI 输出的 JSON 后端先校验，不合格就重试一次 |
| 安全 | 所有密钥只放 .env，不进代码、不发群、不截图；模型密钥只在后端；用户数据按 user_id 隔离（Supabase 行级权限） |
| 隐私 | 两周内只用公开样例资料，不放真实用户资料（资料会发给第三方模型厂商） |
| 可访问性 | 正文 ≥ 15px、辅助文字 ≥ 13px；可点击区域 ≥ 44×44；文字对比度 ≥ 4.5；支持浅色和深色主题；尊重“减少动态效果”设置 |
| 兼容 | 电脑 Chrome / Edge / Safari 最新版；窄屏不出现横向滚动 |

## 验收与指标

**演示验收（第 10 天）**：用公开课的真实 PDF 现场走完下面 8 步，全部通过才算 MVP 完成。

- [ ] 定目标：确认拆解卡后左栏出现今天三件
- [ ] 交资料：一讲 PDF 出学习文档，知识点带页码
- [ ] 提问：回答标页码，点开能看到那一页原文
- [ ] 做题：5 道题在一张卡里做完，错题进错题本
- [ ] 补一补：第三件做完，小满告诉明天的三件
- [ ] 跳到明天：演示开关生效
- [ ] 第二天：小满先开口，第一件是昨天的错题；能换强度
- [ ] 做完三件：看板上掌握度变化可见

**AI 评测线**（换模型、改提示词前后各跑一次，分数不降才发布）

| 能力 | 评测集 | 达标线 |
| --- | --- | --- |
| 问答出处 | 30 条标注问答 | 页码和原句核对通过 ≥ 95% |
| 资料外问题 | 20 条资料里没有的问题 | 全部诚实说明 |
| 出题 | 每讲抽 20 道 | 答案正确、能在原文里找到依据，按主方案里的评测表打分 |

**上线后看的指标（MVP 先埋点，不设目标值）**

- 次日回来率：第一天交过资料的用户，第二天打开的比例。
- 断档回归率：连续 2 天以上没来的用户，之后又回来的比例。
- 三件事完成率：打开的那天，三件里做完几件。
- 错题重做后的正确率。

## Bad case 库与数据飞轮

每一次出错都进一个 bad case 库；修好后它变成评测用例，以后每次改提示词都要重新考一遍。这样用的人越多，库越大，小满越准，而且同一个问题不会犯第二次。两周内就搭起来，演示和测试里发现的问题当天就能修、当天能回归。

（图：Bad case 飞轮 · 5 步循环——见在线文档）

**从哪里收**

| 来源 | 怎么进库 |
| --- | --- |
| 用户点 👎、“这道题有问题”（回答、题目、学习文档上） | 自动，带上当时的输入输出；可选填一句哪里不对 |
| 用户纠正（改了学习文档、说“不对”） | 自动 |
| 后端自动检测：出处核对失败、JSON 不合格、出题自检答案对不上、报错或超时 | 自动 |
| 测试、演示、关卡评审里发现的 | 组员在 Supabase 表格里手动加一行，不用写代码 |
| 评测没过的用例 | 自动 |

**库里每条记什么**

| 字段 | 说明 |
| --- | --- |
| 能力 | 问答 / 出题 / 学习文档 / 开场与建议 / 理解用户想干嘛 |
| 输入 | 用户的话、用了哪一讲哪几页 |
| 实际输出 / 期望输出 | 小满说了什么，应该说什么 |
| 模型和提示词版本 | 哪个模型、哪版提示词产生的 |
| 问题类型 | 编造出处 / 答错 / 没理解意图 / 题目有误 / 格式错 / 语气不对 / 太慢 |
| 严重程度 | 高（编造、答错）/ 中 / 低 |
| 状态 | 新 / 已分诊 / 已修复 / 已回归 / 不修（写原因） |
| 负责人、修复说明 | 谁在修、改了哪版提示词的哪一处 |

**谁来做、多久做一次**

- **D**：建 bad case 表，接好自动采集。**B / C**：在回答、题目、文档卡上加 👍 / 👎 和“这道题有问题”。
- **A** 每天看一遍新增，按问题类型分给 **E**（问答、开场、意图）和 **F**（出题、文档）。高严重度当天修。
- 改提示词一次只改一处，版本号 +1；发布前跑完整评测集和所有已修复的 case，分数不降才发布。
- 关卡评审时看四个数：新增多少、修了多少、回归通过率、同类问题有没有复发。

两周内库里只有公开样例资料。以后放真实用户的输入前，要先告知用户并去掉个人信息。

## 里程碑、风险与待定

（图：两周路线图 · 4 段、3 道关——见在线文档）

每道关当天下午现场演示，过了才往下走；第 5 天不通就当场砍范围。每人每段做什么见[两周分工方案](https://claude.ai/artifact/5wuYkKqTCmyiB54cq24UiE)。

**风险**

| 风险 | 应对 |
| --- | --- |
| 第 5 天一份 PDF 走不通 | 先砍图片和扫描件，学习文档只留要点和知识点 |
| 整讲全文太长或太贵 | 前 2 天测一次最多能带几讲；超了只带当前一讲 |
| 底座很新、只有一个作者，可能有 bug | 第 1–2 天先跑通它自带的全部测试；不改它的编排，只在单独模块里加功能；底座的问题由 D 修 |
| 主模型出错或额度用完 | 自动切备用模型 |
| 小组零基础，进度失控 | 每天群里三句话；关卡现场演示，没过当场砍范围 |
| 速度目标定得不准 | 非功能要求里的时间是目标值，第 1–2 天实测后调整 |
| 用户多了以后模型成本成倍上涨 | MVP 记录每次调用的 token；触发“成本估算”里的任一条件就上自建知识库 |
| 同一个问题反复出现 | bad case 修好后变成评测用例，每次改提示词都重新考一遍 |
