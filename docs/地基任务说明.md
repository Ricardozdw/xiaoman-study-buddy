# 地基任务说明（交给搭地基的 AI）

> 2026-11-04 · 读者：负责搭地基的 AI 代码助手（能读写本仓库、能运行命令）。
> 开工前先读：仓库根目录 `CLAUDE.md` / `AGENTS.md`、`README.md`、`docs/分工方案.md`、`docs/交接/` 下 6 份交接文档、`docs/xiaoman/MVP-PRD.md`、`docs/xiaoman/技术实现主文档.md`、底座的 `CONTRIBUTING.md`。

## 背景

“小满学习搭子”是一个以对话为主的学习网页。6 个技术小白组队两周做 MVP，按模块分成 A（节奏与体验）+ 5 条模块线：资料、问答、练习、计划、看板与上线。5 条线会**同时开工、各自独立完成、最后一次性合并**。

你的任务是搭“地基”：一个能跑起来的空壳，让 5 条线拿到后只在自己的地方加东西，最后能顺利合到一起。**你不实现任何一条线的业务功能**，只搭共用部分、立好约定，并给每条线留好位置。

## 地基要包含什么

**后端**（在现有 Personal-Agent 底座上，Python 3.12 + FastAPI）
- 底座在本地能启动，它自带的 `pytest` 和 `tests/golden/` 回归全绿。
- 能用 Supabase 的 Postgres（通过 `DATABASE_URL`），本地没配时仍可用 SQLite 跑起来。登录沿用底座的网页会话，不用 Supabase 登录。
- 关掉或不暴露 MVP 用不到的底座功能：飞书 / 微信渠道、网页抓取、写草稿、安全输入区、对外的通用记忆卡。危机识别和出站护栏保留。
- 我们自己的后端代码放在独立的包里（例如 `app/study/`），不往底座的 `app/main.py` 里堆。每条线一个子模块，再加一个公共部分。
- 数据表：建好技术主文档“数据表”一节里的表，外加 bad case 表（字段见 PRD“Bad case 库与数据飞轮”）。每张表带 `user_id`，按用户隔离。
- 接口：把技术主文档“接口清单”里的接口全部挂在 `/api` 下，先返回符合约定格式的假数据，让前端可以直接对接。底座已有的 `/api/session`、`/api/chat`、`/api/feedback` 沿用。
- 一个“AI 能力”的完整范例：版本化提示词文件（`app/prompts/<名字>/vN.md`）+ 后端函数，经底座模型网关调用。调用时记录输入 / 输出 token 和所属能力，输出 JSON 不合格时重试一次，出错时写一条 bad case。其他线照这个范例接自己的能力。
- “取资料内容”函数的空壳：按讲返回带页码的全文，以后换知识库只改这里。

**前端**（新建在 `web/`，React + TypeScript + Vite）
- 只有一个对话页：中间是对话流和输入框（＋ 交资料、@ 指定某讲），左栏放今天三件事、强度切换和我的资料，右侧是按需打开的工作台。
- 一套卡片组件，覆盖 PRD 里的 7 种卡片：目标拆解、进度、文档摘要、题目、建议、重排、收工。卡片能原地更新、做完收成一行。各线复用这些组件，不再各做一套。**样式先做朴素、干净的版本即可，不用花功夫打磨**：视觉和交互之后由 A 找参考定方向再设计。重点是组件对外的用法（传什么数据、有哪些按钮和回调）清晰、稳定，并写进给各线的说明里，这样 A 以后改样式不影响各线。颜色、字号等用统一的变量，方便 A 之后整体替换。
- 小满的头像和状态表情可以先用占位图，接口留好。
- 每条线一个自己的文件夹，放一个能显示的占位，让各线从这里开始。
- 只调后端 `/api`，不直接调模型；后端没好时用和接口约定一致的假数据。
- 满足 PRD 的可访问性和兼容要求：正文 ≥ 15px、可点区域 ≥ 44×44、浅色和深色主题、窄屏不横向滚动。

**约定和检查**
- 一份接口约定文件（OpenAPI，FastAPI 自动生成即可），前端用它生成类型。
- 一份写给 5 条线的简短说明：自己的代码放哪、哪些文件是共用的（改动要先找 A）、怎么接 AI 能力、怎么写 bad case 和记 token、怎么跑起来和跑测试。放在 `docs/` 下，并在 README 里加上入口。
- 自动检查：每次推送和 PR 都跑后端测试和前端的构建 / 测试；底座原有的 `harness-golden` 保留。
- 每晚用真实模型跑的 `golden-nightly` 在没配密钥前停用，或改成没密钥时跳过。

## 必须遵守

- 遵守 `CLAUDE.md` 里的产品规则和禁止事项。
- 不动底座的安全规则（`CONTRIBUTING.md` 第 3 节“不要动的东西”），不删、不跳过它的测试。改提示词要新建版本，不改旧版。
- 密钥只放 `.env`，不提交；需要新的配置项时写进 `.env.example`，并附上说明。
- 不用 Dify、不用知识库、不上 Redis；两周内只用公开样例资料。
- 不替各线实现业务功能，只留位置和范例。
- 新增依赖要少，选主流、稳定的版本。

## 做到什么算完成

- 按 README 能在一台新电脑上把后端和前端都跑起来，打开就是对话页的空壳，左栏、工作台、7 种卡片都能用假数据显示出来。
- 后端 `pytest`、底座金标回归、前端构建和测试全部通过，自动检查是绿的。
- `/docs` 里能看到并点通全部接口，返回的数据格式和约定一致。
- AI 能力范例在没配模型 key 时也能用底座的离线占位跑通，并能看到它记下的 token 记录和一条测试用的 bad case。
- 5 条线的文件夹和写给各线的说明都在，说明里写清了哪些文件是共用的。
- 工作在一个分支上完成，最后提一个 PR 合进 `main`。PR 说明写清做了什么、怎么验证、还有哪些没做或需要 A 决定的事。

## 有不确定的地方

不要猜：跟仓库里的文档对不上、或者需要做取舍的地方，写进 PR 说明的“需要 A 决定”一节，交给 A（项目负责人）决定。
