# 交接 · 2 问答线

> 先读 [分工方案](../分工方案.md)：产品规则、技术约定、协作方式对所有人都适用。

## 你负责什么

用户在对话里问资料里的问题，小满回答并标出处，点开能看到原文。另外负责判断用户每句话想干嘛。对应 PRD 的 **F3 资料问答**，演示的第 3 步。从界面、接口到提示词都由你完成。

范围：
- “问答”这个 AI 能力：问题 + 一讲全文（带页码）→ 回答，关键结论标【第 N 页】并摘一句原句；边生成边显示。
- 出处核对：后端检查摘的原句是否真的在那一页，对不上就去掉这条出处。
- 输入 @ 指定问哪一讲；不指定就问最近在学的一讲。
- 点【第 N 页】在右侧工作台看那一页原文，引用的句子高亮。
- 资料里没有的，说“你的资料里没提到”，再给通用知识。
- 回答下的 👍 / 👎，点 👎 可以填一句哪里不对。
- “理解用户想干嘛”这个 AI 能力：用户一句话 → 提问 / 出题 / 调安排 / 闲聊，再分给对应的线处理；闲聊交给底座原有的对话。

## 要做出什么

- 30 条标注好的问答，页码和原句核对通过率 ≥ 95%。
- 20 条资料里没有的问题，全部诚实说明，不编。
- 问答 5 秒内开始出字。
- 一句话能分对去向：“关键路径怎么算”→ 问答，“出几道题”→ 练习线，“今天只有 15 分钟”→ 计划线。
- 点 👎 后，这条回答进 bad case 库。

## 和别人对接

- **资料线**：用它的“取资料内容”函数拿全文，用“资料页”显示原文某一页。
- **练习线、计划线**：“理解用户想干嘛”判断出是出题或调安排时，交给他们的入口。入口的格式事先商量好。
- **看板与上线线**：出处核对失败、👎 都要进 bad case 库；调用的 token 要记录下来；30 + 20 条问答评测集交给他们放进评测里。
- **A**：小满回答的语气按 A 的文案规范来。

## 必须遵守

- 不编造出处，对不上的出处宁可去掉。
- 一次只带一讲的全文，跨讲提问提示用户用 @ 选讲。
- 改提示词要新建下一版文件，评测分数不降才算改好。
