# 交接 · 5 看板与上线线

> 先读 [分工方案](../分工方案.md)：产品规则、技术约定、协作方式对所有人都适用。

## 你负责什么

让用户看得见自己在进步，也让团队看得见 AI 做得好不好、花了多少钱，并把产品准备好上线。对应 PRD 的 **F8 看板**、“Bad case 库与数据飞轮”、“成本估算”里要做的部分，以及上线准备。演示第 8 步的看板部分。

范围：
- 看板：用户问“这周学得怎么样”出摘要卡，完整版在右侧工作台，包括这周学了几天、本周做题数、待重做错题、每讲掌握度、目标进度。
- bad case 库：建表，各线的出错和用户反馈都写进这里；团队直接在 Supabase 表格里看和加，不做管理页。
- 成本记录：每次调用模型都记下输入 / 输出 token，能按用户、按能力汇总。
- 评测：一条命令就能跑完各线的评测集和已修好的 bad case，出一份报告，能看出这次是否比上次差。
- 模型对比：主、备两个模型在评测上对比准确、速度和单价，给出主模型建议和真实单价。
- 上线准备：部署配置、上线前检查（密钥、自动测试、演示 8 步），交给 A 上线。

## 要做出什么

- 看板不出现“连续 N 天”；第二天重做错题后，掌握度变化看得见。
- 任何一条线出错或用户点了 👎、“这道题有问题”，bad case 表里都能看到一行，带当时的输入输出、模型和提示词版本。
- 能拿出一张按用户、按能力的 token 和费用汇总。
- 评测同一份跑两次，分数基本一样。
- 主备模型对比表，加上一句“建议谁当主”。
- 上线前检查清单全部打勾。

## 和别人对接

- **练习线**：掌握度、做题数、错题的数据。
- **计划线**：“这周学了几天”、目标进度。
- **资料线、问答线、练习线、计划线**：各自的 AI 能力怎么把出错和 token 写进来，统一用你定的方式，事先告诉大家；各线的评测集收到你这里。
- **A**：每天分诊 bad case 用你的表；上线由 A 决定和执行。

## 必须遵守

- 看板只和自己的过去比，不显示断签和红色失败标记。
- bad case 库和评测集里只放公开样例资料。
- 评测会花不少 token，不要无意义地反复跑。
