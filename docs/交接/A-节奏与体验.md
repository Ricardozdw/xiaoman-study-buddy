# 交接 · A 节奏与体验

> A 不写某一条的业务代码。各线负责人见 [地基给各线](../地基给各线.md)（2026-11-04 确认）。

> 先读 [分工方案](../分工方案.md)：产品规则、技术约定、协作方式对所有人都适用。

## 你负责什么

整个项目的节奏和最终体验：定开工和上线日期、盯进度、验收每条线交来的模块、统一界面和卡片的体验、写小满的文案和表情、每天分诊 bad case，最后把所有模块合并到 main 并上线。

## 要做出什么

- **一份排期**：开工日、各线交付日、合并日（至少留 1–2 天）、上线日，大家认可。
- **体验规范**：7 种卡片（目标拆解、进度、文档摘要、题目、建议、重排、收工）长什么样、怎么出现和收起；小满的 5 个露出时刻（每天第一次打开、状态变化、收工和里程碑、空状态、拆解卡和建议卡）用哪个表情、说什么话。各线照着做，做出来的东西风格一致。
- **小满的文案**：开场白、建议卡、收工、中断后回来三种情况的说法，交给计划线放进提示词。语气温和、不追责、不施压。
- **bad case 分诊**：每天看一遍新增的 bad case，按类型分给对应的线（问答 / 意图 → 问答线，出题 / 错题 → 练习线，学习文档 → 资料线，开场 / 建议 → 计划线），高严重度当天处理。
- **验收与合并**：每条线交来时，对照 PRD 的验收标准在浏览器里点一遍；全部合并后完整走一遍演示 8 步，问题当场分给对应的人修。
- **上线**：合并完成、演示 8 步全部跑通后上线；准备演示脚本和录屏备份。

## 做到什么算完成

- 上线后的网页能用一门公开课的真实 PDF 走完演示 8 步，不靠截图。
- 每条 PRD 验收标准都有人在浏览器里确认过。
- 界面上没有违反 8 条产品规则的地方，比如出现“连续 N 天”、责备的话，或者一次推两张卡。
- 上线时 bad case 库里没有未处理的高严重度问题。

## 你说了算的事

- 共用部分（对话页骨架、卡片组件、数据表、接口约定）要不要改、怎么改。
- 各线之间的边界和冲突。
- 什么时候砍范围。比如交付前某条线做不完，可以先砍图片和扫描件，学习文档只留要点和知识点。
