## 4. 接口契约

所有数据从现有服务端会话识别用户；不接收调用方伪造的 user_id。前端 `credentials: include`，外层响应继续使用 `{ok, status, mock, data}`，错误使用 HTTP 状态及 detail。

| 接口 | 参数 / 用法 |
| --- | --- |
| `POST /api/session` | 使用现有浏览器会话；Workbench 初始化会调用，不另建账号体系 |
| `GET /api/practice/materials` | 当前用户在本线独立上传入口导入的 PDF 列表 |
| `POST /api/practice/materials` | multipart `file`，返回 lecture_id、filename、页数、字数；成功后自动选中。重复文件复用且概览重新刷新 |
| `POST /api/quizzes` | lecture_id、count 1–15、difficulty easy/medium/hard、mode practice/review、question_ids、可选 task_id |
| `GET /api/quizzes/{quiz_id}` | 当前用户的题组、进度和已有作答；作答前不返回答案、解析、引用原句 |
| `PATCH /api/quizzes/{quiz_id}/progress` | question_id、answer（可为空）、seconds、paused；成功后才退出；不含 confidence |
| `POST /api/attempts` | question_id、answer、quiz_id、seconds；必须带 quiz_id 才能获得同组同题的幂等语义 |
| `GET /api/practice/paused` | 可继续的未完成题组；首页最近一条置顶，其余折叠 |
| `GET /api/practice/learning?lecture_id=...` | 当前 PDF 的原题链最新结果、反馈状态及完整作答历史；页面“全部”仅列 has_attempt 的条目 |
| `GET /api/practice/stats?lecture_id=...` | 当前 PDF 去重后的 correct_count / wrong_count / consolidate_count / reported_count / accuracy；accuracy 允许 null |
| `GET /api/mistakes` | 真实待巩固错题，按原题链最近结果去重并排除有效反馈 |
| `GET /api/practice/review-due?on=YYYY-MM-DD` | 给后续统筹对接的到期查询；仅查询，不修改真实时钟 |
| `POST /api/practice/reports` | question_id、必选单一 category、选填 reason、quiz_id / attempt_id；同用户同题再次提交更新已有反馈 |
| `GET /api/practice/reports/{question_id}` | 本用户反馈详情；storage=server，不代表维护者已阅读 |
| `DELETE /api/practice/reports/{question_id}` | 撤回后按保存的对错恢复统计和分类；失败保持原状态 |

category 为 `answer / ambiguous / source / other`。题目问题反馈不是公共答案审核，不修改题目标准答案，不删除题目，不影响其他用户。

review 显式提供 question_ids 时，只生成这些可练的已答题（包括普通答对），不自动补入推荐题；已反馈和越权题拒绝，超过上限拒绝，count 小于所选数时也拒绝。前端必须检查空选、超限与加载中重复点击。未传 question_ids 的旧推荐用法仍保留，但页面不会这样调用开始复习。

## 5. 数据与统计：不要另起一套状态

- 复用既有 `Question / Attempt / KnowledgePoint / StudyEvent / BadCase / StudyFile / MaterialPage`，没有改共用模型、表结构或新增数据库迁移。
- 本地真实数据保存在现有服务端数据库（本次为 SQLite），不是浏览器 localStorage 模拟保存。Supabase 生产环境未验收。
- 题组和暂停进度在 `practice_quiz_created` 事件中；前端 localStorage 仅记活动题组、界面和未提交答案草稿，不是作答的唯一来源。
- 带 quiz_id 的同组同题第一次提交为准；重复点击不能覆盖第一次答案。重新练习有新 quiz_id 和新 Attempt，旧作答不改写。
- `Question.source_json.practice.original_id` 指向原题链根，`parent_question_id` 记录直接变式来源；引用保留 PDF 页码和核对后的片段。不要只按 question_id 独立累计所有变式或用旧题错误覆盖后来已答对的结果。
- `learning.snapshot` 按当前用户、原题链取最近一次 Attempt。有效反馈会排除这一原题链（包括相关变式），避免传播争议题；相同知识点下其他独立原题不受影响。
- 新反馈有效状态、编辑/撤回历史在 `StudyEvent.name=practice_question_feedback`；BadCase 仍作索引，source 为 question_feedback。兼容以前只写 BadCase 的记录，撤回 tombstone 防止旧反馈被重新激活。
- 有效反馈不计入正确率分子或分母、不计入错题/待巩固，不进入自动或手动再练；撤回不要求重答。反馈和知识点更新同事务，失败整体回滚，前端保留表单。
- `accuracy` 是同一统计范围内去重后的答对数 / 有效题目数，不是整个 PDF 掌握度；无有效题目为 null。不能把 KnowledgePoint 的均分、少量练习或重复复练说成整份 PDF 已掌握。
- `wrong_count` 与 `consolidate_count` 都是有效答错数；旧 priority 保留字段形状但始终 false。历史 confidence 元数据只为读取兼容，页面不使用。不要依据这些旧值恢复优先级或新增加权分数。
- 变式复用原知识点，提示词要求换情境、条件或干扰项；出题后核对引用和盲答。模型自检不能保证答案一定正确。

## 6. 共用对话页接入（需要 A / 统筹处理）

现有共享页面只改了练习线自己的 Placeholder，让开发者能进入独立验收页。没有修改 Shell 或其他线的组件。

入口组件：`PracticeWorkbench({lectureId?, taskId?, onActiveChange?, onComplete?})`。

- 传入 lectureId 时以正式资料线的真实讲次为准；不可把未知讲次的地基样例回退当成用户上传资料。
- 用户点击计划任务发起练习时，明确传 taskId。无 taskId 时不额外创建计划任务。
- `onActiveChange(true)` 时由共用层收起历史答案、关闭右侧原文面板；独立题卡无法控制 Shell 外部已有消息。
- `onComplete` 中刷新计划、看板等共享状态。不要只因答错就阻止“做了算完成”。
- 目前原文入口展开已核对的引用及页码，不是一个可滚动定位的 PDF 阅读器；右侧阅读器定位需要正式资料层与 A 衔接。
- 独立生产构建命令见第 8 节，输出 `web/dist/practice/`。正式上线时需由 A 决定挂载位置和构建入口，不能把源码预览路径直接当生产 URL。

## 7. 结合最新 main 必须核对的三个语义问题

截至 main `7d32733` 的代码检查结果，以下尚未完成联调，本线不擅自修改其他线：

1. **原题链与反馈排除。** `app/study/plan/service.py:gather_inputs` 直接按 question_id 取最后一次 Attempt，没有合并 original_id，也没有读取有效反馈。这可能使原题变式答对后原题仍被计划为错题，或已反馈题继续进入“补一补”。统筹应复用本线统一快照/到期查询，而不是复制另一套判断；同时检查 `_auto_complete` 如何识别原题与变式的完成记录。
2. **讲次 ID。** 计划线当前按 `lec-N` 组织正式讲次；本线独立上传工具生成 `ml-basics-<文件哈希前缀>`。接正式资料线前须统一课程/讲次映射与 MaterialPage 来源。不能盲目替换字符串或依赖讲次不存在时的样例回退，也不能覆盖历史外键。
3. **时钟与完成。** 本线今日/本周/到期按真实上海日期，尚未跟计划线演示时钟联动。本线显式 task_id 可标记对应任务完成并发 `practice_quiz_completed`；计划线新 main 也会从作答自动同步完成。整合时统一完成通知和日期来源，再回归跨天、暂停和答错仍完成，避免两条链路重复或口径不一致。
