## 目标
目标该收尾时，小满出建议卡；用户点了“完成”才算完成；给一张完成卡（模板统计，不调 AI）。

## 接口（`app/study/v2/completion.py` + `routes.py`）
- `GET /api/v2/completion` → `{suggest: bool, reason: "all_done"|null, card: {...}|null, done: bool}`
  - `suggest=true` 当：所有单元的“学第 N 讲”都勾过，且最近一次阶段测验分数 ≥ 70（达标线写成常量 `PASS_SCORE = 70`）。
  - `card`（不管 suggest 与否都能算，给前端预览）：`days`（有作答或勾任务的不同日期数）、`attempts`（总作答数）、`first_score` / `last_score`（第一次和最近一次阶段测验分数）、`hardest_unit`（答对率最低的单元名）、`label: "模拟"` 或 `""`（数据里有模拟题时标模拟）。
  - `done=true` 表示已经完成过。
- `POST /api/v2/completion/confirm` body：`{reason: "suggested"|"user_said"}` → `goals.status = "done"`，`summary_json.v2.completed_at` = 今天 → 返回 `card`。**只能由用户点击触发**（规则 11）。
- `POST /api/v2/completion/undo`（当天可撤销）→ 恢复 `status = "active"`。
- 用户在对话里说“我学完了 / 考完了”时：问答线的意图识别现在不认识这句话，**这张卡不改问答线**；前端（T07）提供“我学完了”的入口按钮即可。

## 不能动
- 其他线代码；不删任何作答、任务、测验记录。

## 验收
- [ ] 全部单元勾完 + 最近测验 75 分 → `suggest=true`；最近测验 60 分 → `suggest=false`。
- [ ] confirm 后 `done=true`，计划线的今天三件不再排新任务（若计划线对 `status=done` 没有处理，在 PR 里写明现象，不要改计划线）。
- [ ] undo 恢复；重复 confirm 幂等。
- [ ] 卡片各项数字和数据库一致；开关关时现有测试全绿；`tests/test_v2_completion.py` 覆盖以上各条和 `user_id` 隔离。
