# T04 · 阶段测验 + 成绩报告（后端）

> 执行：Codex · 分支 `codex/t04-assessment` · 依赖：T03 已合并 · 先读 README 和 `docs/v2/V2-方案.md` 11.3

## 目标
每个阶段学完（或这一阶段开始满 7 天）时，出一套 10 题的阶段测验；做完给成绩报告；错题自然进计划线的“补一补”，看板自然统计。

## 做法：复用练习线，不直接写题目表
- 出题：对这一阶段的每个单元调用练习线 `app/study/practice/service.py::create_quiz(uid, QuizBody(lecture_id="lec-N", count=k, difficulty="easy"))`，k 按单元数平分 10 题（余数给前面的单元）。没配模型时练习线自己会出模拟题（标“模拟”）。
- 判分：每道题调用 `service.submit(uid, AttemptBody(question_id, answer, quiz_id))`。掌握度、错题、作答记录都由练习线照常处理。
- V2 只在 `assessments` 表里记：这次测验包含哪些题（`question_ids_json`）、分数、报告。

## 接口（`app/study/v2/assessment.py` + `routes.py`）
- `GET /api/v2/assessment/due` → `{due: bool, stage: {no, title, unit_nos}, reason: "stage_done"|"seven_days"|null, open_id}`。
  - `stage_done`：这一阶段所有单元对应的“学第 N 讲”任务都在计划里勾过（读 `plan_tasks`，`kind=learn`、`status=done`、`ref.lecture_no` 在阶段内）。
  - `seven_days`：这一阶段 `started_at` 到今天满 7 天（用计划线的“今天”，以便演示日期开关生效：`app/study/plan/demo.py::today(user_id)`）。
  - 已有 `open` 的测验时返回它的 `open_id`，不重复出。
- `POST /api/v2/assessment/start` → 出题、建 `assessments` 行（`status=open`）→ 返回 `{id, stage, questions:[{id, stem, options}], label, mock}`（**不返回答案**）。
- `POST /api/v2/assessment/{id}/submit` body：`{answers: {question_id: "A"|"B"|"C"|"D"}}`（没答的题算未答，不算错）→ 逐题调练习线 `submit` → 算报告 → `status=submitted` → 下一阶段 `started_at` = 今天 → 返回报告。
- **报告**：`{score: 0-100（答对题数/已答题数×100，取整）, units:[{no, title, correct, total}], weak_unit_nos:[答对率<60%的单元], next_stage}`。文案字段 `summary` 用模板，例如“这一阶段做了 10 题，对了 7 题。第 3 单元再看一眼会更稳。”——**不说“不及格”，不评判人**。
- **占当天一件**：提交后，把今天计划里第一件未完成的 `kind=practice` 任务标为完成（走计划线现有 `service.patch_task(user_id, task_id, status="done")`，等同用户自己勾）；今天没有练一练就不动。
