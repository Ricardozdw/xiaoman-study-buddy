# T02 · V2 地基：开关、两张表、路由骨架

> 执行：Codex · 分支 `codex/t02-v2-foundation` · 依赖：无 · 先读 `docs/v2/任务卡/README.md`

## 目标
给 V2 搭好地基：环境变量开关、两张新表、`/api/v2/*` 路由骨架。**这张卡不做任何业务逻辑**，后面 T03–T07 都建在它上面。

## 要做的
1. **开关** `app/study/v2/__init__.py`：`def enabled() -> bool`，读环境变量 `XIAOMAN_V2`，值为 `1`/`true` 时为真（每次调用读，测试能用 monkeypatch 切换）。
2. **表** `app/study/v2/models.py`（继承同一个 `Base`，风格照 `app/study/common/models.py`）：
   - `goal_outlines`：`id`、`user_id`(索引)、`goal_id`、`status`（`draft` / `accepted` / `replaced`）、`goal_type`（`exam` / `course` / `skill`）、`title`、`units_json`（`[{"no":1,"title":"…","points":["…"]}]`）、`stages_json`（`[{"no":1,"title":"…","unit_nos":[1,2,3],"started_at":""}]`）、`label`（`AI 整理，可以改` 或 `模拟`）、`created_at`、`updated_at`。
   - `assessments`：`id`、`user_id`(索引)、`outline_id`、`stage_no`、`status`（`open` / `submitted`）、`question_ids_json`、`score`（0–100，可空）、`report_json`、`created_at`、`submitted_at`。
   - 让 `ensure_schema()` 创建它们：在 `app/study/v2/models.py` 里被导入即可注册；在 `app/study/common/db.py` 的 `ensure_schema` 里加一行 `import app.study.v2.models  # noqa: F401`（**只加这一行**）。
   - 在 `app/study/common/schema.sql` 里把两张表加进行级安全的表清单和注释（照 `goals` 的写法）。若 `deploy/xiaoman/study_schema.py` 按清单生成 SQL，同步加上。
3. **路由** `app/study/v2/routes.py`：`router = APIRouter()`，先只有 `GET /api/v2/status` → `{"enabled": true, "version": "2.0-min"}`（用 `app/study/common/http.py` 的 `pack`，`mock=False`）。鉴权照其他线用 `require_user`。
4. **注册**：在 `app/study/router.py` 里**只在 `enabled()` 为真时** `include_router(v2_router)`。注意注册时机是应用启动时；测试里需要开 V2 的，用 fixture 设环境变量后重新建 app（照现有测试里建 `TestClient` 的方式）。
5. **测试** `tests/test_v2_foundation.py`：开关关 → `/api/v2/status` 返回 404；开关开 → 200 且 `enabled: true`；两张表能写能读，`user_id` 隔离（A 用户读不到 B 用户的行）。

## 不能动
- 其他线的任何文件（`app/study/{plan,qa,practice,materials,dashboard}/`、`web/`）。
- `app/study/common/` 里除上面写明的一行 import 和 `schema.sql` 清单外的任何内容。

## 验收
- [ ] `XIAOMAN_V2` 不设时：`pytest` 全绿、跳过数与 main 相同；`/api/v2/status` 404。
- [ ] `XIAOMAN_V2=1` 时：`/api/v2/status` 200，`{"enabled": true}`。
- [ ] 新测试覆盖开关两种状态和 `user_id` 隔离。
- [ ] CI 的 `postgres-rls` 通过。
