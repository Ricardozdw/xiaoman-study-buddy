> 关系：组员继续按 [MVP PRD](../xiaoman/MVP-PRD.md) 开发、第 10 天演示；A 同期在自己的分支上按本方案迭代，新功能放在 `XIAOMAN_V2=1` 开关后面，关掉就是原 MVP。

## 1. 定位

**一句话**：小满是帮你把学习目标坚持到完成的 AI 学习搭子。你说想学成什么样，把手上的资料交给它（没有也行）；它每天告诉你该学的三件事，记住你学到哪、错在哪，定期考考你，陪你走到目标完成。

**不是**：问一句答一句的问答工具（ChatGPT、NotebookLM，围绕资料）；只管出题的题库；靠连续打卡施压的打卡 App。
**是**：围绕“你和你的目标”，主动安排、持续跟进的那个“人”。

**人群**：学生到上班族，有明确学习目标的人。
**主打（对外先讲这一类）**：**下班后备考证书的上班族**（例如 PMP、教资、CPA、软考）。时间碎、动机强、最怕中断后放弃。（A 已确认）

## 2. 痛点与解法

| 痛点 | 表现 | 小满的解法 |
| --- | --- | --- |
| 不知道今天学什么 | 目标大、资料多，打开不知从哪下手 | 大目标拆成每天最多三件：学新的 / 练一练 / 补一补 |
| 学了记不住，也没人记 | 错题、遗忘散落各处，AI 也不记得你 | 学习记录就是记忆：错题自动进补一补，第二天接得上 |
| 看不到进步 | 学了一个月心里没底 | **阶段测验** + 看板：掌握度、目标进度都看得见 |
| 一中断就放弃 | 任务堆积、愧疚，干脆不学 | 不追责、不打卡、不堆积；回来只出一张卡调整节奏 |

## 3. 主流程

```
定目标 ──→ 交资料（可选，随时可补）──→ 拆解（目标拆解卡，点了才生效）
                                              │
            ┌─────────────────────────────────┘
            ▼
     每天三件（学新的 / 练一练 / 补一补）──→ 收工
            │                     ▲
            ├─ 每个阶段结束 ──→ 阶段测验 ──→ 成绩报告（薄弱处进补一补）
            │
            └─ 中断后回来 ──→ 一张卡调整节奏
            ▼
       目标完成 ──→ 完成卡 + 学习总结 ──→ 下一个目标？
```

和 MVP 的区别只有四处：**目标更通用、资料可选、多了阶段测验、多了目标完成**。中间的“每天三件 / 收工 / 中断回来”沿用 MVP。

## 5. 关键设计

### 5.1 定目标（通用）

一次只问一题，每题都有快捷回复，也能自己输入，可以“先跳过”（跳过的不算用户的选择）。

1. **想学成什么样？**（快捷回复：考过一个证书 / 学完一门课或一本书 / 掌握一项技能）
2. **什么时候想完成？**（具体日期 / 一个月内 / 三个月内 / 不急）
3. **每天大概有多少时间？**（15 / 30 / 50 分钟 → 默认强度）
4. **手上有课件、教材或考纲吗？**（有，现在交 / 有，晚点交 / 没有）
5. 只对“考证”和“课程”追问：**学到哪了？**

> 和 MVP 的差别：不再要求用户填“一共几讲”。单元数来自资料目录或学习大纲。

### 5.2 资料：不强制，两条路，随时升级

| | 有资料 | 没资料 |
| --- | --- | --- |
| 拆解依据 | 资料的目录、章节 | `goal.outline` 生成的学习大纲（标“AI 整理，可以改”） |
| 学新的 | 学习文档，提问标页码 | 小满讲要点，标“通用知识，没有出处” |
| 练一练 / 阶段测验 | 从资料出题，带出处 | 通用题，标“通用题，没有出处”，题量少一些 |
| 提示 | — | 持续轻提示“交资料能排得更准” |
| 题量上限 | 按强度 | 通用题每天最多 3 道（A 已确认） |

- 后来交了资料 → 建议卡“按你的资料重新排一下？”，点了才生效、可撤销。
- 资料和目标对不上（目标 PMP，交的是 Excel 教程）→ 先问一句，不直接按资料排。

### 5.3 拆解：按“单元”而不是“讲”

- **单元**：可以是一讲、一章、一个技能点。来源优先级：资料目录 > 学习大纲。
- **阶段**：几个单元组成一个阶段，例如“基础 → 强化 → 冲刺”。按目标日期、每天时间、单元数算出每个单元大约几天。
- **每天三件**照旧从三处取：学新的（下一个单元）、练一练（学过的单元）、补一补（错题和快忘的点）。
- 继续用计划线的规则算，**不让 AI 直接排每天的任务**。AI 只负责生成大纲，结果可预测、可撤销。

### 5.4 阶段测验

- **什么时候出**：每个阶段学完；或学满 7 天，取先到的一个。小满出一张卡：“考考这一阶段？大约 15 分钟”，可以“晚点再考”。
- **形式**：一套 10–15 道单选题，覆盖这一阶段的单元，一张卡里做完（沿用练习线“一组题一张卡”）。
- **成绩报告**：总分、每个单元的掌握度变化、薄弱的知识点。薄弱处自动进之后的“补一补”。
- **规则**：测验占当天三件中的一件（不加件数）；分数只用来调整掌握度和排程，不评判人，不说“你不及格”。

### 5.5 目标完成

- **判定**：所有单元学完，并且最后一次阶段测验达到设定的线（默认 70 分）；或者用户自己说“我考完了 / 学完了”。
- **完成卡**：学了多少天、做了多少题、掌握度从多少到多少、最难的那一块是怎么攻下来的（`goal.summary` 生成，标“AI 整理，可以改”）。
- **下一步**：“定下一个目标？”或“先休息一阵”。完成记录永远保留。

## 6. 产品规则

MVP 的 8 条全部继续有效。V2 补充 3 条：

9. 没有资料出处的内容（通用讲解、通用题、学习大纲）必须标出来，不冒充资料原文。
10. 阶段测验占当天三件中的一件，不加件数；分数不用来评判人。
11. 目标完成以用户的确认为准：小满可以建议“看起来可以收尾了”，用户点了才算完成。

## 7. 技术做法（不和组员撞车）

- **分支**：A 在 `v2/*` 分支上做，定期把 `main` 合进来。
- **开关**：`XIAOMAN_V2=1` 才启用新流程；关掉时，定目标、拆解都走计划线原来的逻辑，第 10 天演示不受影响。
- **代码位置**：后端 `app/study/v2/`，前端 `web/src/lines/v2/`。不改组员负责的文件；要扩展计划线时，优先在计划线留好的接口外面包一层。
- **新 AI 能力**（各带版本化提示词和小评测集）：`goal.outline`（学习大纲）、`assess.generate`（阶段测验组卷，复用练习线出题）、`goal.summary`（学习总结）。
- **数据**：尽量复用现有表（goals、chapters、questions、attempts、knowledge_points）。新增两张：`assessments`（一次阶段测验）、`goal_outlines`（学习大纲，可被用户修改）。

## 9. 迭代节奏

| 段 | 时间 | 做什么 | 怎么算完成 |
| --- | --- | --- | --- |
| 0 | 现在（1–2 天） | 本方案 + 可点击原型 | A 在原型里走通新流程并确认 |
| 1 | 组员开发期间 | 通用定目标、学习大纲（没资料那条路）、阶段测验、目标完成 | 开关打开后，没资料也能从定目标走到目标完成 |
| 2 | MVP 合并之后 | 按资料目录拆解、多份资料、资料与目标匹配、交资料后升级计划 | 有资料和没资料两条路都能走通 |
| 3 | 上线后 | 看指标、访谈 5–10 个用户、bad case 闭环 | 根据数据决定下一步 |

**上线后看的指标**：次日回来率、断档回归率、三件完成率、阶段测验分数变化、目标完成率。

## 10. 已确认的决定（2026-11-06，A 按建议值确认）

1. 主打人群：**下班后备考证书的上班族**，产品能力兼顾学生。
2. 阶段测验频率：**每个阶段学完，或最长 7 天一次**，取先到的。
3. 目标完成分数线：最后一次阶段测验 **默认 70 分**。
4. 没资料时的通用题：**每天最多 3 道**。
5. 下一步：**先做可点击原型**，A 在原型里走通新流程后，再进入第 1 段开发。
