## 接口

都在 `/api` 下。打开 http://127.0.0.1:8787/docs 能点。返回外面一层是：

```json
{ "ok": true, "status": "ok", "mock": true, "data": {} }
```

`mock: true` 表示还是假数据或离线占位。

合同里的「POST /chat（SSE）」：底座已有的 `POST /api/chat` 是一次性整段 JSON，不是流。地基没有改它。流式占位是 `POST /api/chat/stream`，现在只回模拟句子。问答线以后再决定是包一层底座，还是换成真的流。

合同没写、地基多留的：

- `PATCH /api/plan/today`：换强度（轻松 / 正常 / 冲刺）。勾选完成走 `PATCH /api/tasks/{id}`
- `GET /api/me/permissions`：合同只有 PATCH
- `POST /api/study/example`、`GET /api/study/usage`、`GET /api/study/bad-cases`：给 AI 范例看结果，不是正式产品接口

前端只调 `/api`。后端没起来时，`web/src/api/mocks.ts` 用同一形状顶上。

## 怎么接一个 AI 能力

照着 `app/study/common/capability.py` 和 `app/prompts/study.example/v1.md`：

1. 新建 `app/prompts/<名字>/v1.md`。名字用小写和点，例如 `qa.answer`。用户的话放进提示词里已有的那种数据块（范例用的是 `<source>`）。
2. 写一个函数：`load_prompt("名字", "v1", ...)`，再调用底座 `chat_json` 或 `chat_text`。
3. 用 Pydantic 检查 JSON。不合格就把失败原因补进提示词，再调一次。还不行就 `write_bad_case(...)`。
4. 像范例那样往 `llm_calls` 写一行，带上 `user_id`、能力名、提示词版本、输入 token、输出 token。

没配模型 key 时，网关会走离线占位，范例也能跑完。

自己改这个范例时，不要改 `v1.md`，新建 `v2.md`，再把 `capability.py` 里的版本号改成 `v2`。

本地看结果（先按 README 把后端跑起来，并在浏览器打开过一次页面，这样才有登录会话）：

- `POST /api/study/example`，正文 `{"text":"每天最多三件事。","page":1}` → 返回摘要，并在 `GET /api/study/usage` 里看到 token
- 同一地址加上 `"demo_failure": true` → `GET /api/study/bad-cases` 里多一条测试用记录，`source` 是 `foundation_demo`
